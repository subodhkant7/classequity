# AG Studio integration

The primary sponsor is a real interactive component, not a screenshot or substitute chart library. `ag-studio` and `ag-studio-react` are both **3.1.0**; their Grid 36.3.0 versions match. `src/components/studio.tsx` uses AgStudio, AgStudioProvider, createWidgets, AgStudioAiModule, createAiHarness, AgReportState, and the documented LLM adapter protocol. The developer's existing trial is applied through AgStudioLicenseManager. No separate unrelated Grid Enterprise licence is registered or assumed. Commercial dependencies retain their terms.

The official starter https://github.com/paypaldev/hackathon-paypal-ag-grid-boilerplate was reviewed: package versions, initial report structure, and OpenAI adapter. Compatible ideas reused are the 24-track widget layout, field/aggregation mappings and server proxy separation. Its OpenAI adapter was not copied wholesale; a smaller typed Gemini adapter translates the actual v3 protocol. Our proxy always requires a valid tenant session, role and durable quota; no public AI endpoint is used.

## Report

Financial overview, group-pricing progress, registered vs financially confirmed seats, sponsorship commitments/funding, pending/failed/unknown payment counts, reconciliation, and comparison across available trips. No historical trip record is fabricated. The report page selector chooses these actual AG report pages. Native AG Grid and chart widgets remain editable. Group Unlock, Funding Assurance, and Payment Integrity are custom widgets using the documented native component interface registered through createWidgets; they display trusted aggregate application context. Their core financial meaning is intentionally fixed; new AI-built analytical views use the native schema-enabled widgets.

Only aggregate sources reach Studio: trip financial summaries, operation status counts, and pricing tiers. No student/parent names, phones, aid eligibility, allocation IDs or recipient mapping exist in a Studio table or tool result. Display dollars are derived from authoritative integer cents. Presentation state is per-user/per-school in ce_dashboard_configuration. It cannot change authoritative financial data.

## Agent boundary

Browser AgLlmAdapter.executeTurn posts the framework request to authenticated `/api/studio/turn`. Server verifies role and quota, discovers/selects a supported Gemini Flash model, supplies authoritative aggregate context, maps conversation messages, function calls and results, and maps tool schemas to Gemini function declarations. The result is translated back into AgLlmResponse and text/tool stream events. Studio's official `directLlmRunner` and `createAiHarness` run a focused school-finance agent. The `school_financial_summary` tool returns permitted aggregates and safe operation IDs/statuses. The `build_financial_view` tool creates actual editable native report pages for funding, comparison, pricing or reconciliation, with validated field mappings. This avoids allowing the model to invent widget IDs or data sources. The default general-purpose five-agent roster was tested but proved unreliable at chart configuration, so it was replaced by this documented custom-agent extension. There are no financial authorization tools. Each turn has bounded input, token budget and provider timeout; each agent run is capped at five turns. Empty model output returns a visible unavailable/error response, never a fabricated success.

Examples: why the trip is pending; verified funding gap; group tier; implications of three withdrawals without assuming obligation increases; report comparisons. Personal assistance requests are outside the schema and system instructions. Gemini cannot decide eligibility or execute money movement.
